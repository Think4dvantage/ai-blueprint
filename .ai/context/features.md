# Feature History & Backlog

## Current Version: v2.3 (shipped)

### Shipped Milestones

| Milestone | What shipped |
|---|---|
| v1.0 | Full `.ai/` blueprint: instructions (00–05), context templates, 14 prompts covering planning workflow (specify→clarify→plan→checklist→tasks→analyze→implement), sync/update prompts, user profile, architect persona, central update mechanism. Pushed to GitHub at Think4dvantage/ai-blueprint. |
| v2.0 | Multi-category restructure: blueprint split into `dev-web` (FastAPI + Vanilla JS), `bp-OPS` (Docker/Traefik/GitHub Actions infrastructure), and `dev-app` (Flutter mobile). Root `.ai/` repurposed as meta-repo instructions. Each category is self-contained with adapted instructions, context templates, and category-specific prompts. |
| v2.1 | Corrected a self-contradiction in `dev-web` on SQLite migrations (`02-backend-conventions.md` and `04-constraints.md` each described two mutually exclusive doctrines — resolved to raw `ALTER TABLE` in `_run_column_migrations()`, no Alembic/`.sql`/`_migrations` table, matching the already-correct Architecture section). Rewrote `dev-web/06-testing-conventions.md` (48 → ~230 lines) with a proven pytest harness: `StaticPool` for in-memory SQLite, `ASGITransport`-based lifespan handling, config-isolation-via-`monkeypatch`, `SimpleNamespace` duck-typing for pure-logic tests, token-fixture pitfalls, time-dependent-fixture guidance, "what not to test." Replaced the broken `AsyncClient(app=app, ...)` example (removed in httpx 0.28). Updated the `dev-web` auth tech stack from `passlib` to direct `bcrypt` (passlib's bcrypt backend breaks under bcrypt ≥4.1). Added a `Security` section and a `Dependencies` (lockfile) section to `dev-web/04-constraints.md`; added async-event-loop-safety, batch-over-loop, scheduler-overlap-guard, and config-resolved-at-call-site guidance to `02-backend-conventions.md`. Added an "always verify current versions before pinning" rule to the shared `05-user-profile.md` (propagated to all 3 categories), with a cross-reference in `bp-OPS`'s existing "never use `:latest`" rule. Added a spec-archiving convention (`git mv` shipped specs to `specs/archive/`) to all 3 categories' Planning Workflow. Learnings sourced from real-world drift observed in two projects built off this blueprint (Lenticularis, LSMFAPI). |
| v2.2 | Repo-hygiene pass on self-identified defects. Created `manifest.json` in all 3 categories (`update-blueprint.md` Step 0 fetched this and 404'd every time — it never existed, so the drift-prevention mechanism was itself always falling back to the hand-maintained table it was meant to backstop). Deleted the dead-weight root `.ai/context/architecture.md` (a meaningless byte-identical copy of `dev-web`'s — this meta-repo has no SQLite/InfluxDB/Traefik of its own) and added the previously-omitted `context/` section to the root File Map. Fixed `dev-web/prompts/update-blueprint.md`'s Framework row (was missing `08-operability.md`, which the Hardcoded Fallback List already had — the two disagreed). Fixed a duplicate `architect.md` row in `bp-OPS/prompts/update-blueprint.md`'s fallback list, found while building its manifest. Added a "Step 2b — Keep manifest.json in Sync" section + checklist item to root `sync.md` so this class of drift can't silently recur. Renumbered `bp-OPS/06-operability.md` → `08-operability.md` and `dev-app/07-observability.md` → `08-operability.md` (title unified to "Operability Conventions") to match `dev-web`'s `08-operability.md` — the numbering both real consumer projects (Lenticularis, LSMFAPI) independently converged on; updated every cross-reference (`00-ai-usage.md` File Maps + Always Read First, `update-blueprint.md` Framework rows + fallback tables, `manifest.json`, `dev-app/02-app-conventions.md`). |
| v2.3 | Added a `context/*-notes.md` "project-notes companion" pattern to all 3 categories, closing a structural gap: `update-blueprint.md`'s two-category model only ever protected `01-project-overview.md` and `context/architecture.md`/`features.md` from being overwritten, so every other instruction file (`02`–`08`) silently destroyed accumulated project-specific detail (real auth/role models, fixed-bug history, real pipeline quirks, real test fixtures) on every blueprint sync — and `sync.md` itself directed that knowledge nowhere else to go. Each blueprint-owned instruction file 02–08 now has a matching `context/<topic>-notes.md` companion (dev-web: `backend-notes.md`, `frontend-notes.md`, `constraints-notes.md`, `testing-notes.md`, `operability-notes.md`, with `07-api-conventions.md` sharing `backend-notes.md`; bp-OPS: `infra-notes.md`, `cicd-notes.md`, `constraints-notes.md`, `operability-notes.md`; dev-app: `app-notes.md`, `api-client-notes.md`, `constraints-notes.md`, `testing-notes.md`, `operability-notes.md`), added to each category's `00-ai-usage.md` ("Framework vs Project Knowledge" section, Always Read First, setup steps, File Map), cross-referenced from the top of each companion instruction file, added to `manifest.json`'s `project_data_files` and `update-blueprint.md`'s project-data row in all 3 categories, and rerouted `sync.md`'s session-discovery step to write here instead of into the blueprint-owned instruction files. Sourced from a contribution reported by the Lenticularis project after real-world drift; the original contribution proposed `dev-web`-only with a `security-notes.md` companion for `04-constraints.md` and no companion for `08-operability.md` — corrected to `constraints-notes.md` (matches the file's actual scope) plus `operability-notes.md`, and extended structurally to all 3 categories with category-appropriate topic names, since the gap was universal, not `dev-web`-specific. |
